# 检索与防幻觉协议（每次交付都必须走一遍）

## 为什么要有这一层

大模型写雅思内容有两个"看起来对、其实错"的高发区：

1. **评分标准混版**。2023 年 5 月官方改过措辞，旧版 `addresses all parts of the task` 至今在教材和网站上大量流传。模型凭记忆写，很容易把两版缝在一起，编出一条"官方从没写过"的标准。
2. **素材数字编造**。"研究表明 73% 的人……"这类句子读起来最像范文，也最不可核。

这两件事的共同解法只有一个：**不许凭记忆写，必须先查；写过之后必须能逐字核回去。**

依据见 `sources.md` 第 23–25 条（RAG / 幻觉分类 / 检索后自评）。

## 第一闸：写之前，先检索

### 什么情况下必须检索

| 场景 | 检索什么 | 不检索的后果 |
|---|---|---|
| 写给分点 | 目标档位的描述语原文 | 凭印象写"7 分要求立场清楚"，可能引的是 6 分那句 |
| 打分 | 每一档的原文，逐档比对 | 直接凭感觉给分，事后无法解释 |
| 写范文 | 话题素材（`fact-registry`）、同题常见论证 | 写出"很多国家都……"的空话，或编数字 |
| 用户问"X 分要什么" | 该档四项描述语 | 给出通用鸡汤 |

**唯一可以不检索的情况**：用户只问"这道题是哪种题型"——题型判定靠 `task2-playbook.md` 的指令句表，不涉及事实。

### 怎么检索

```bash
# 按话题 + 中文关键词（中英混着查最准，语料是英文写的）
python scripts/rag_search.py "小作文 overview 关键特征" --task 1 --k 5
python scripts/rag_search.py "cohesion mechanical 衔接" --k 5
python scripts/rag_search.py "band 7 task response 立场" --task 2 --k 4
python scripts/rag_search.py "学费 大学" --file fact-registry --k 3
```

读结果的顺序：**先看 `[R:编号]`，再看正文，最后决定用不用**。相关度低但内容对的，可以用；相关度高但答非所问的，不要硬塞。

### 检索结果怎么用

- **官方描述语**：只许**整句原样引用**，不许改写后仍称"官方"。要压缩就明确说"用一句话说就是……"，并且不给引用号。
- **事实素材**：只许用 `fact-registry.md` 里登记的。表里标"待核"或"仅定性"的，不许加数字。
- **范文句子**：一律不抄。抄一句就是抄袭，而且是考官最熟悉的那种抄袭。取词可以，取句不行。

## 第二闸：写的时候，边写边挂引用号

### 引用格式

```text
[A档要求的写法]
Task Response 要拿 7 分，立场必须清楚且全程不变 —— 对应 [R:T2.TR.7]
"A clear and developed position is presented."

[B档：不可以这么写]
Task Response 7 分要求"立场清晰、论证充分、逻辑严密"（官方原话）。
→ 问题：这句话不是官方原话，是把 7 分和 8 分揉在一起的中文概括，却贴了"官方原话"的标签
```

规则：

1. 引用号写在句末或引文后，格式固定 `[R:编号]`。
2. 引用号后面紧跟的英文引文，**必须是该块的原文子串**（程序会逐字比对）。
3. 一个引用号对应一块，不要 `[R:全文件]`。
4. 中文解释不用挂引用号；只有"声称是官方原文"的英文才必须挂。

### 不许做的三件事

| 不许 | 为什么 | 程序能不能抓 |
|---|---|---|
| 编一个看起来合理的编号（如 `T2.TR.10`） | 官方没有 10 档以上的 TR 描述语，容易被当成"9 分之上还有" | 能（ID 不存在） |
| 引文改两个词（如把 `the main parts` 写成 `all parts`） | 一字之差就是旧版，意思从"主要部分"变成"全部" | 能（逐字比对） |
| 把中文翻译说成"官方原话" | 中文是我写的解释，不是官方文本 | 部分能（引号内若无英文原文会告警） |

## 第三闸：写之后，跑两个脚本

```bash
# 1) 引用核对：编号是否存在、引文是否逐字对得上
python scripts/verify_citations.py 输出文件.md

# 2) 语言体检：字数、句长、连接词、模板句、AI 高频词
python scripts/essay_stats.py 范文.txt --task 2
```

**两个都过，才算可以交付。** `verify_citations.py` 退出码为 1 时，不许交付——先把引用改对。

## 检索不到怎么办（降级路径）

按顺序降，不许跳级：

1. **换词再查一次**。中文查不到就加英文关键词，或改用 `--file` 限定文件。
2. **降到定性表述**。查不到"70% 的国家"，就写 `a growing number of countries`。
3. **改成机制论证**。不写数据，写"为什么会这样"——机制成立不需要外部证据（详见 `fact-registry.md` 第四节）。
4. **直接告诉用户"这条我没核到"**。在输出里写一句"这个数据我查不到可靠出处，标待核，建议不要写进考场作文"。

第 4 条是保底，也是最容易被忽略的一条。**宁可承认不知道，也不要给一个看起来专业的假数字。**

## 常见失败模式（照这个自查）

| 症状 | 实质 | 修法 |
|---|---|---|
| 输出里引用号格式五花八门 | 没统一规范 | 只允许 `[R:XXX]`，方括号 + 大写 ID |
| 每条都给引用号，但引文是中文 | 把引用号当装饰 | 引用号只服务英文原文 |
| 同一段引了 4 个号 | 堆砌，读者无法核 | 一段最多 2 个，其余改成自己的话 |
| 打分说"7 分左右"但不说是哪一条 | 无法复核 | 必须写"卡在 [R:T2.TR.7] 的 over-generalise 这一条" |
| 用了 `fact-registry` 里"待核"的素材还加了数字 | 二次幻觉 | 立即改成定性，或换成已核实的 |
| 引用号对，但引文是从另一档抄的 | 张冠李戴，最难发现 | 重跑 `verify_citations.py`（逐字比对会抓出来） |

---

## 一句话原则

**每一个"官方说"都要能点开看到原文；每一个数字都要能指到出处；做不到就降级成说人话。**
